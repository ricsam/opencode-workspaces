Use a values file rather than a long list of `--set` arguments:

```bash
helm show values opencode-workspaces/opencode-workspaces > values.production.yaml
helm upgrade --install opencode-workspaces opencode-workspaces/opencode-workspaces \
  --namespace opencode-workspaces \
  -f values.production.yaml
```

## Images

The default repositories are:

```yaml
image:
  repository: ghcr.io/ricsam/opencode-workspaces-server
  tag: ""
  pullPolicy: IfNotPresent

workspaceImage:
  repository: ghcr.io/ricsam/opencode-workspaces-runtime
  tag: ""
  pullPolicy: IfNotPresent
```

An empty tag resolves to `appVersion` from the chart. Released charts therefore pull immutable version tags such as `0.2.2`.

## Public URL and proxy headers

```yaml
publicURL: https://code.example.com
trustProxyHeaders: true
```

Enable trusted proxy headers only when the application is behind infrastructure that removes untrusted incoming forwarding headers. The public URL must match what browsers use.

## Workspace defaults

```yaml
workspace:
  storageClass: rook-ceph-block
  storageSize: 10Gi
  idleTimeout: 30m
  runtimeClassName: kata
  imagePullSecret: ""
  nodeSelector:
    kubernetes.io/hostname: workspace-node-1
  resources:
    requests:
      cpu: 500m
      memory: 768Mi
    limits:
      cpu: "4"
      memory: 6Gi
```

- `idleTimeout: 0s` disables idle scale-to-zero.
- Resource changes apply when the controller next reconciles a workspace.
- A runtime class is strongly recommended when users are not mutually trusted.

## Control-plane resources

```yaml
resources:
  requests:
    cpu: 100m
    memory: 128Mi
  limits:
    cpu: "1"
    memory: 512Mi
```

Only one control-plane replica is currently supported because workspace lifecycle reconciliation and the built-in setup flow assume a single active instance.

## NetworkPolicy

```yaml
networkPolicy:
  enabled: true
  workspaceInternetEgress: true
  workspaceClusterEgress:
    - namespace: ai-gateway
      ports: [80]
```

When enabled, policies:

- allow ingress to the control plane;
- allow control-plane access to PostgreSQL and workspace HTTP ports;
- allow DNS resolution;
- deny workspace access to RFC1918 destinations;
- optionally allow workspace internet egress.

`workspaceClusterEgress` is an explicit allowlist for in-cluster dependencies. Each entry permits TCP from workspace pods to all pods in the named namespace on only the listed ports. This is useful for an internal AI gateway service while RFC1918 egress remains denied by default.

Your CNI must enforce Kubernetes NetworkPolicy. Review the rendered rules against your cluster DNS, database, ingress, and egress architecture before deployment.
